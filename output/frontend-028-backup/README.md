# RoadAware frontend — แผนที่การคาดการณ์รายช่วงถนน (ต้นแบบงานวิจัย)

เว็บแอปแบบ static (HTML/CSS/JavaScript ล้วน ไม่มี build หรือ dependency ที่ต้องติดตั้ง) สำหรับผู้ใช้ทั่วไป: สำรวจแผนที่ประเทศไทย เลือกพื้นที่ เลือกช่วงถนนทางหลวงที่มีข้อมูล กำหนดวัน/ช่วงเวลา แล้วดูค่าคาดการณ์และประวัติที่บันทึกจาก backend API V3 ในเครื่อง ผลทั้งหมดมาจาก API จริง ไม่มีข้อมูลสำรองหรือค่าที่แต่งขึ้น

ไฟล์: `index.html`, `styles.css`, `app.js` (แอปหลัก) · `debug.html`, `debug.js` (หน้าตรวจสอบสำหรับนักพัฒนา ไม่อยู่ในเมนูของแอป)

อ้างอิง: [frontend integration contract](../workflow/api/frontend-integration-contract-v3.md), [คู่มือ backend API](../workflow/api/backend-api-runbook-v3-th.md), [แผน Analytics และ Dashboard](../workflow/analytics-and-dashboard-plan-th.md)

## เริ่มใช้งาน (สอง terminal ที่ root ของ repo)

Terminal 1 — backend (ใช้ `.venv` ที่มีอยู่แล้ว):
```
.venv/bin/python backend/scripts/run_api_server.py
```
รอจน log แสดง `Application startup complete` (อาจใช้เวลาหลายสิบวินาที)

Terminal 2 — frontend แบบ static:
```
python3 -m http.server 5173 --bind 127.0.0.1 --directory frontend
```

เปิดเบราว์เซอร์ที่ **http://127.0.0.1:5173/** (ต้องเป็น origin นี้ เพราะ CORS ของ backend อนุญาตเฉพาะ origin ที่กำหนด)

หยุด: กด `Ctrl+C` ใน terminal แต่ละอัน

ค่าเริ่มต้นของ API คือ `http://127.0.0.1:8000` ถ้าต้องการชี้ไปที่อื่นให้เปิด `http://127.0.0.1:5173/?api=http://127.0.0.1:8001` (การเปลี่ยน API ต้องโหลดหน้าใหม่ จึงไม่มีผลเก่าค้างอยู่)

## ต้องใช้อินเทอร์เน็ตสำหรับแผนที่
- ไลบรารีแผนที่ Leaflet 1.9.4 โหลดจาก CDN `unpkg.com` (ตรึงเวอร์ชันและมี SRI integrity) และภาพแผนที่จาก OpenStreetMap `https://tile.openstreetmap.org/` พร้อมแสดง attribution ตาม [นโยบาย tile ของ OSM](https://operations.osmfoundation.org/policies/tiles/) โหลดเฉพาะ tile ที่มองเห็น ไม่มีการ prefetch
- ถ้าไม่มีอินเทอร์เน็ตหรือ CDN ล้มเหลว หน้าแอปจะแจ้งว่าแผนที่แสดงไม่ได้ แต่ยังเลือกจังหวัดหรือปุ่ม “กรุงเทพฯ และปริมณฑล” แล้วใช้งานต่อได้ ถ้าเฉพาะภาพ tile โหลดไม่ได้จะมีแถบแจ้งเตือนเล็ก ๆ แยกจากสถานะบริการข้อมูล
- ข้อมูลคาดการณ์ทั้งหมดมาจาก backend ในเครื่องเท่านั้น

## ขั้นตอนใช้งาน
1. หน้าเว็บตรวจ `GET /ready` อัตโนมัติ มุมขวาบนแสดง “บริการข้อมูลพร้อม” เมื่อได้ HTTP 200 และ `research_backend_ready: true` ถ้าไม่พร้อมจะแสดง “บริการข้อมูลไม่พร้อม” พร้อมปุ่ม “ลองอีกครั้ง” ระหว่างนี้เลื่อนดูแผนที่ได้ แต่ปุ่มข้อมูลถูกปิด
2. **เลือกพื้นที่** — คลิกตำแหน่งบนแผนที่ (ค้นหาในกรอบ ±0.1°/0.2°/0.4° รอบจุด ตาม “ระยะค้นหารอบจุด”), กด “กรุงเทพฯ และปริมณฑล” (bbox `100.4,13.6,100.8,14.0`), “ค้นหาถนนในมุมมองนี้” (ใช้ขอบแผนที่ปัจจุบัน จำกัดให้อยู่ใน lon 97–106, lat 5–21 และไม่เกิน 20° ต่อแกน) หรือเลือกจังหวัด (กรอบ ±0.3° รอบจุดอ้างอิงของจังหวัดจาก `GET /api/v1/provinces`) ระบบเรียก `GET /api/v1/segments` ทีละ 100 รายการ; แสดง “แสดง N จาก M ช่วงถนนในพื้นที่นี้” และปุ่ม “แสดงช่วงถนนเพิ่ม” ใช้ `next_cursor` จริง พื้นที่ที่ไม่มีข้อมูลแสดงว่า “ไม่มีช่วงถนนที่รองรับ” ไม่มีการ snap ไปยังถนนที่ใกล้ที่สุด
3. **เลือกช่วงถนน** — คลิกเส้นถนนบนแผนที่หรือเลือกจากรายการ (ชื่อทางหลวง · จังหวัด · ลำดับช่วง) เส้นที่เลือกถูกเน้นสีเข้ม เส้นอื่นเป็นสีเทากลาง ๆ รหัส `segment_id` อยู่ใน “รหัสอ้างอิงช่วงถนน”
4. **วันและช่วงเวลา** — วันที่เริ่มต้น 2026-11-12 (รองรับ 2024-01-01 ถึง 2027-12-31), “ทั้งวัน” (`daily`) หรือ “ช่วง 6 ชม.” (`6h` + `time_block`) แล้วกด **ดูการคาดการณ์**
5. แท็บ “การคาดการณ์” แสดง `expected_recorded_count`, `density_per_km`, `segment_km`, แถบสีจาก `colour`/`colour_hex` พร้อม `colour_text` จริง และสถานะ `research_scenario`; รายละเอียด (`horizon`, `issue_time_local`, `model_version`, `component_used`, `routing_reason`, `data_period`, `source_availability`, `caveats`) อยู่ในส่วนพับ เส้นที่เลือกบนแผนที่ใช้ `colour_hex` เฉพาะหลังได้ผลคาดการณ์ของอินพุตปัจจุบันเท่านั้น
6. แท็บ “ประวัติที่บันทึก” เรียก `POST /api/v1/spatial/history` ด้วยอินพุตเดียวกัน แสดง `n_selected_records`, ช่วงเวลา, `counts_by_year`, `counts_by_time_block`, หมวดหมู่ที่บันทึก และ `period_status` (ช่วงที่ไม่อยู่ใน catalog แสดงว่า “ไม่ทราบ ไม่ใช่ศูนย์”)

### การจัดการสถานะ
- เปลี่ยนพื้นที่ → ยกเลิก request ที่ค้าง ล้างถนน การเลือก และผลทั้งหมด; เปลี่ยนช่วงถนน/วันที่/รูปแบบ/ช่วงเวลา → ล้างผลและสีบนแผนที่ทันที
- ระหว่างคาดการณ์ อินพุตที่มีผลต่อผลลัพธ์และการคลิกพื้นที่ถูกปิดชั่วคราว และทุก response ตรวจ generation/controller ก่อนแสดง response ที่ล้าสมัยถูกทิ้ง
- เครือข่ายล้มเหลว, timeout 30 วินาที หรือ HTTP 503 → สถานะเป็น “บริการข้อมูลไม่พร้อม” และล้างผลทั้งหมด; HTTP 400/404/อื่น ๆ แสดงข้อความภาษาไทยพร้อม “รายละเอียดทางเทคนิค” (HTTP status, `error.code`, `error.message`) แบบพับไว้ ถ้าประวัติล้มเหลวด้วย 4xx ผลคาดการณ์ของอินพุตเดียวกันยังคงแสดง และมีปุ่มลองโหลดประวัติใหม่

## หน้าตรวจสอบสำหรับนักพัฒนา (diagnostics)
เปิด **http://127.0.0.1:5173/debug.html** (ไม่มีลิงก์จากแอปหลัก) — กำหนด base URL, ส่ง request ใด ๆ และดู HTTP status + JSON ดิบ มีปุ่มลัด ready / metadata / provinces / evaluation / segments / prediction / baseline (เปรียบเทียบเท่านั้น) / history และ “bad request” ที่ส่ง body ผิดโดยตั้งใจไปที่ `POST /api/v1/spatial/predictions` (คาดว่าได้ HTTP 400) การแก้ค่าใด ๆ ล้างผลเดิมทันที

ทดสอบบริการไม่พร้อม: ในแอปหลักเปิด `http://127.0.0.1:5173/?api=http://127.0.0.1:8999` ต้องเห็น “บริการข้อมูลไม่พร้อม” และปุ่มข้อมูลถูกปิด แล้วกลับไปที่ `http://127.0.0.1:5173/` หรือหยุด backend ชั่วคราวแล้วกด “ลองอีกครั้ง” หลังเปิดใหม่

## ข้อจำกัด
- ต้นแบบงานวิจัย `production_ready = false`; ไม่มี auth, deploy, HTTPS, ข้อมูลเรียลไทม์ หรือคำแนะนำเส้นทาง
- `expected_recorded_count` คืออัตราจำนวนรายการบันทึกที่คาดไว้ (research) ไม่ใช่ความน่าจะเป็นรายบุคคล ห้ามรวมหลายช่วงถนนเป็นความเสี่ยงของเส้นทาง สี `base` ไม่ได้แปลว่าปลอดภัย
- วันที่หลัง 2025-12-31 เป็นฉากทัศน์วิจัย ไม่มีข้อมูลจริงให้เทียบ; ถนนที่ไม่รองรับและประวัติที่ไม่อยู่ใน catalog = ไม่มีข้อมูล ไม่ใช่ศูนย์
- Baseline และ evaluation ไม่อยู่ในแอปหลัก (ดูได้จาก debug.html); ห้ามรวม/เทียบ evaluation ข้าม scope หรือ unit
- ลำดับ “ช่วงที่ N” ในรายการนับเฉพาะช่วงถนนของทางหลวงเดียวกันที่โหลดแล้วในพื้นที่ (เรียงตาม `segment_id`)
- ยังไม่มีชุดทดสอบอัตโนมัติสำหรับ frontend
