# RoadAware frontend — วางแผนเส้นทางพร้อมผลประเมินรายช่วงถนน (ต้นแบบงานวิจัย)

เว็บแอปแบบ static (HTML/CSS/JavaScript ล้วน ไม่มี build หรือ dependency ที่ต้องติดตั้ง) สำหรับผู้ใช้ทั่วไป: ค้นหาต้นทางและปลายทาง **ใดก็ได้ในประเทศไทย** ดูเส้นทางขับรถจริง แล้วดูจุดสีบนช่วงถนนที่มีผลประเมินจาก backend API V3 ในเครื่อง พร้อมประวัติที่บันทึกเมื่อแตะจุด

การวางแผนเส้นทาง **ไม่ขึ้นกับ** ขอบเขตข้อมูลของแบบจำลองหรือสถานะ backend: เส้นทางที่ไม่มีช่วงถนนที่รองรับ หรือเมื่อ backend ไม่พร้อม ยังแสดงเส้นทางเต็มได้ตามปกติ ส่วนที่ไม่มีผลประเมิน = ไม่ทราบ ไม่ใช่ปลอดภัยหรือศูนย์

ไฟล์: `index.html`, `styles.css`, `app.js` (แอปหลัก) · `assets/thailand-boundary.geojson` + `assets/PROVENANCE.md` (ขอบเขตประเทศสำหรับแสดงผล) · `debug.html`, `debug.js` (หน้าตรวจสอบสำหรับนักพัฒนา ไม่อยู่ในเมนูของแอป)

อ้างอิง: [frontend integration contract](../workflow/api/frontend-integration-contract-v3.md), [คู่มือ backend API](../workflow/api/backend-api-runbook-v3-th.md), [product direction](../workflow/product-direction.md)

## เริ่มใช้งาน (สอง terminal ที่ root ของ repo)

Terminal 1 — backend (ใช้ `.venv` ที่มีอยู่แล้ว):
```
.venv/bin/python backend/scripts/run_api_server.py
```
รอจน log แสดง `Application startup complete` (อาจใช้เวลาหลายสิบวินาที) — ไม่จำเป็นต่อการดูเส้นทาง แต่จำเป็นต่อผลประเมิน

Terminal 2 — frontend แบบ static (ต้องเสิร์ฟผ่าน HTTP เพราะแอปโหลด `assets/thailand-boundary.geojson`):
```
python3 -m http.server 5173 --bind 127.0.0.1 --directory frontend
```

เปิดเบราว์เซอร์ที่ **http://127.0.0.1:5173/** (ต้องเป็น origin นี้ เพราะ CORS ของ backend อนุญาตเฉพาะ origin ที่กำหนด) หยุด: `Ctrl+C` ในแต่ละ terminal

ค่าเริ่มต้นของ API คือ `http://127.0.0.1:8000`; ชี้ไปที่อื่นด้วย `http://127.0.0.1:5173/?api=http://127.0.0.1:8001`

## บริการภายนอก (ต้องใช้อินเทอร์เน็ต) — เป็นบริการสาธารณะสำหรับทดลอง ไม่ใช่โครงสร้างระบบจริง

ปลายทางทั้งหมดอยู่ใน object `CONFIG` ต้น `app.js`

| ใช้ทำอะไร | บริการ | เงื่อนไข |
|---|---|---|
| ค้นหาสถานที่ | Photon demo `https://photon.komoot.io/api/?q=…&limit=6&bbox=97,5,106,21` ([docs](https://github.com/komoot/photon)) | ใช้ได้ระดับพอประมาณ ไม่รับประกันการให้บริการ; แอปเรียกเฉพาะเมื่อกด “ค้นหา”/Enter, ไม่เกิน 1 ครั้ง/วินาที (รวมทุกช่อง), cache คำค้นเดิม, timeout 15 วินาที, ยกเลิก/ทิ้งผลที่ล้าสมัย; ไม่ใช้ Nominatim |
| เส้นทางขับรถ | OSRM demo `https://router.project-osrm.org/route/v1/driving/…?overview=full&geometries=geojson&steps=false` ([API](https://project-osrm.org/docs/v5.24.0/api/), [demo policy](https://github.com/Project-OSRM/osrm-backend/wiki/Demo-server)) | ใช้เพื่อทดลองแบบไม่ใช่เชิงพาณิชย์ ≤ 1 ครั้ง/วินาที ไม่มี SLA; แอปเรียกเฉพาะเมื่อกด “ดูเส้นทาง” |
| แผนที่ | Leaflet 1.9.4 จาก `unpkg.com` (SRI) + tile OpenStreetMap ([tile policy](https://operations.osmfoundation.org/policies/tiles/)) | แสดง attribution เสมอ (บนมือถือย้ายไปมุมขวาบนเพื่อไม่ให้ถูกแผงด้านล่างบัง) โหลด tile เฉพาะในกรอบประเทศไทย |

ขอบเขตประเทศ: Natural Earth 1:50m (public domain) คัดลอกไว้ใน `assets/` — ใช้แสดงผลโดยประมาณเท่านั้น ไม่ใช่เขตแดนทางกฎหมาย และไม่เกี่ยวกับข้อมูลของแบบจำลอง (ดู `assets/PROVENANCE.md`)

ข้อมูลผลประเมินและประวัติทั้งหมดมาจาก backend ในเครื่องเท่านั้น ไม่มีข้อมูลสำรอง ค่าจำลอง หรือ fallback

## ขั้นตอนใช้งาน

1. **ต้นทาง/ปลายทาง** — พิมพ์ชื่อสถานที่แล้วกด “ค้นหา” (หรือ Enter) ระบบแสดงผลลัพธ์พร้อมประเภท/ถนน/อำเภอ/จังหวัด ต้อง **แตะเลือก** รายการที่ถูกต้องเอง (ระบบไม่เลือกผลแรกให้อัตโนมัติ เช่น “มหาวิทยาลัยศรีปทุม” มีหลายวิทยาเขต “เขาใหญ่” มีหลายแห่ง) ผลที่ไม่ใช่ `countrycode: TH` หรืออยู่นอกขอบเขตประเทศถูกกรองออก การแก้ข้อความหลังเลือกแล้วจะยกเลิกสถานที่ที่เลือกและเส้นทางปัจจุบัน
   - หรือกด **เลือกต้นทางบนแผนที่ / เลือกปลายทางบนแผนที่** แล้วแตะจุดบนแผนที่ (ตั้งชื่อเป็นพิกัด ไม่มี reverse geocoding) จุดนอกประเทศไทยถูกปฏิเสธ กด “ยกเลิก” หรือ Esc เพื่อออก
   - ปุ่ม **สลับต้นทาง–ปลายทาง** สลับทั้งสถานที่และข้อความ (ถ้ามีเส้นทางอยู่แล้วจะคำนวณใหม่)
   - ลิงก์ “ลองตัวอย่าง” เติมคำค้น มหาวิทยาลัยศรีปทุม / อุทยานแห่งชาติเขาใหญ่ และค้นหาจริง ผู้ใช้ยังต้องเลือกผลที่ถูกต้องเอง
2. **วันและเวลาออกเดินทาง** — ค่าเริ่มต้นคือวันนี้และเวลาปัจจุบัน (จำกัดช่วง 2024-01-01 ถึง 2027-12-31) เวลาออกเดินทางถูกแปลงเป็นช่วง 6 ชม. ที่แบบจำลองรองรับ (`00-06`/`06-12`/`12-18`/`18-24`) และแจ้งให้ทราบว่าไม่ใช่ผลรายชั่วโมง ทุกจุดใช้ช่วงเวลาเดียวกันตามเวลาออกเดินทาง (ไม่ได้คำนวณเวลาถึงแต่ละจุด; ถ้าเวลาเดินทางข้ามช่วงจะมีหมายเหตุ) ตัวเลือก “ภาพรวมทั้งวัน” (`daily`) อยู่ใน “ตัวเลือกช่วงเวลาของผลประเมิน”
3. **ดูเส้นทาง** — แสดงหมุด A/B เส้นทางตามถนนจริง ระยะทางและเวลาขับโดยประมาณจาก OSRM (ไม่รวมจราจรจริง) ถ้าจุดที่เลือกห่างจากถนนที่ OSRM snap ไปเกิน 100 ม. จะแสดงเส้นประและข้อความว่าเส้นทางเริ่ม/สิ้นสุดที่ถนนใกล้ที่สุด ไม่ได้แปลว่าขับเข้าถึงจุดนั้นได้ `NoRoute` / `NoSegment` / 429 / เครือข่ายล้มเหลว แสดงข้อความภาษาไทยพร้อมปุ่มลองอีกครั้ง ไม่มีการวาดเส้นตรงแทน
4. **ผลประเมินตามเส้นทาง** (แยกสถานะจากเส้นทาง) — เมื่อ `GET /ready` พร้อม:
   1. เรียก `GET /api/v1/segments?bbox=<กรอบเส้นทาง+~1 กม., จำกัดใน lon 97–106 lat 5–21>&limit=500` ทีละหน้าตาม `next_cursor` จนครบ (แสดงความคืบหน้า; ไม่ถือว่าหน้าแรกคือทั้งหมด; ถ้าเกิน 40 หน้าหรือ cursor ไม่เปลี่ยน ถือว่าโหลดไม่ครบและแจ้ง error)
   2. จับคู่กับเส้นทาง (ดูกฎด้านล่าง) แบบแบ่งเป็นชุดและคืน main thread ระหว่างชุด
   3. เรียก `POST /api/v1/spatial/predictions` ทีละ ≤ 128 `segment_id` ด้วยวันที่/ช่วงเวลาที่เลือก ตรวจว่าแต่ละแถวตรง `segment_id` และ `target_date` ตามลำดับ
   4. วาดวงกลมที่ตำแหน่งบนเรขาคณิตจริงของช่วงถนนที่จับคู่ได้ สีจาก `colour_hex` และคำอธิบายจาก `colour_text` ของ response คำอธิบายสี (legend) สร้างจากค่าที่ได้จริง เส้นทางส่วนอื่นเป็นสีเทา = ไม่มีข้อมูล
   - ไม่พบช่วงที่จับคู่ได้ → “ยังไม่มีข้อมูลประเมินในเส้นทางนี้” เส้นทางยังแสดงครบ
   - backend ไม่พร้อม → แจ้ง “ขณะนี้ยังดูผลประเมินไม่ได้” พร้อมปุ่มลองอีกครั้ง เส้นทาง ต้นทาง ปลายทาง วันเวลา ยังอยู่ครบ
   - batch ใดล้มเหลว → ไม่แสดงจุดสีใดเลย (ไม่แสดงผลบางส่วนเหมือนครบ) พร้อมปุ่มลองอีกครั้ง
5. **แตะจุดสี** หรือเลือกจาก “รายการช่วงถนนตามลำดับเส้นทาง” → เน้นช่วงถนนบนแผนที่ และแสดงการ์ด “ผลประเมิน” (`expected_recorded_count`, `density_per_km`, `segment_km`, สี + `colour_text`, `research_scenario`, รายละเอียดที่มา) และแท็บ “ประวัติที่บันทึก” (`POST /api/v1/spatial/history` ด้วยวันที่/หน่วย/ช่วงเวลาเดียวกัน, `period_status` ช่วงที่ไม่อยู่ใน catalog = ไม่ทราบ ไม่ใช่ศูนย์)

### กฎจับคู่ช่วงถนนกับเส้นทาง (client-side, โดยประมาณ)
- ฉายพิกัดเป็นเมตรแบบ equirectangular รอบจุดกลางเส้นทาง สร้าง grid index ขนาด 250 ม. ของเส้นทาง และกรองช่วงถนนด้วย bbox ก่อน
- สุ่มจุดตัวอย่างแบบระยะเท่ากันตามความยาวช่วงถนน ทุก ≤ 100 ม. (จุดกึ่งกลางของแต่ละส่วนย่อย)
- ช่วงถนนถือว่า “อยู่บนเส้นทาง” เมื่อจุดตัวอย่าง **≥ 50%** อยู่ห่างจากเส้นทาง **≤ 50 ม.** — ถนนที่ตัดผ่านเส้นทางจึงไม่ถูกนับ ใช้ midpoint เดียวหรือ bbox ตัดกันไม่ได้
- วงกลมวางที่จุดตัวอย่างกึ่งกลางของส่วนที่ตรงกับเส้นทาง เรียงตามระยะจากต้นทาง
- เป็นการจับคู่โดยประมาณ ไม่ใช่การยืนยันระดับการนำทาง และไม่รายงานสัดส่วนของเส้นทางที่ไม่มีข้อมูล เพราะยังไม่มีความยาวซ้อนทับที่ตรวจสอบแล้ว

### แผนที่จำกัดเฉพาะประเทศไทย
- `maxBounds` = lat 5.1–20.95, lon 96.9–106.1 พร้อม `maxBoundsViscosity: 1`; `minZoom` คำนวณใหม่ตามขนาดหน้าจอ (ซูมออกได้ไม่เกินระดับที่เห็นทั้งประเทศ) และคำนวณใหม่เมื่อ resize
- พื้นที่นอกประเทศไทยถูกปิดด้วยสีพื้นทึบ (world polygon ที่เจาะรูด้วย polygon ทุกส่วนของ MultiPolygon) ใน pane ที่อยู่เหนือ tile แต่ใต้เส้นทาง/จุด/หมุด หน้ากากรับคลิกและปฏิเสธการเลือกจุด
- ถ้าโหลดขอบเขตประเทศไม่ได้: ปิดการเลือกจุดบนแผนที่ (การค้นหายังกรองด้วย `countrycode: TH` + กรอบ lon 97–106 lat 5–21) ถ้า Leaflet/CDN โหลดไม่ได้: ยังค้นหา ดูสรุปเส้นทาง และผลประเมินได้ ถ้า tile ล้มเหลว: แสดงแถบแจ้งเตือนเล็ก ๆ

### การจัดการสถานะ
- แยก generation/AbortController ของ: การค้นหาแต่ละช่อง, เส้นทาง, ผลประเมิน และประวัติ ผลที่ตอบกลับหลังอินพุตเปลี่ยนจะถูกทิ้งเสมอ
- เปลี่ยน/แก้ต้นทางหรือปลายทาง → ยกเลิกเส้นทางและผลประเมิน; เปลี่ยนวันที่/เวลา/รูปแบบ → ล้างจุดสีทันที แล้วโหลดผลใหม่หลังหยุดพิมพ์ ~0.45 วินาที (ถ้ายังอยู่ช่วง 6 ชม. เดิมไม่โหลดซ้ำ) เส้นทางคงอยู่
- ความล้มเหลวของบริการใด ๆ ไม่ลบข้อความ สถานที่ที่เลือก หรือวันเวลาที่กรอกไว้

### มือถือ / เดสก์ท็อป
- มือถือ (≤ 760 px): แผนที่เต็มจอ + แผงด้านล่างที่ยุบ/ขยายได้ (แตะหัวแผง) แผงเป็นพื้นที่เลื่อนเดียว ไม่มีการเลื่อนแนวนอน ปุ่มและช่องกรอกสูง ≥ 44 px ช่องกรอกตัวอักษร 16 px (ไม่ซูมอัตโนมัติบน iOS) ขณะเลือกจุดบนแผนที่แผงจะยุบให้อัตโนมัติ
- เดสก์ท็อป: แผนที่ + แถบด้านข้าง 440 px

## หน้าตรวจสอบสำหรับนักพัฒนา
**http://127.0.0.1:5173/debug.html** (ไม่มีลิงก์จากแอปหลัก) — ส่ง request ใด ๆ ไปยัง backend และดู HTTP status + JSON ดิบ

ทดสอบ backend ไม่พร้อม: เปิด `http://127.0.0.1:5173/?api=http://127.0.0.1:8999` แล้ววางแผนเส้นทาง — เส้นทางต้องแสดงครบ และส่วนผลประเมินแจ้งว่ายังดูไม่ได้พร้อมปุ่มลองอีกครั้ง

## ข้อจำกัด
- ต้นแบบงานวิจัย `production_ready = false`; ไม่มี auth, deploy, ข้อมูลเรียลไทม์ การนำทางแบบเลี้ยวต่อเลี้ยว หรือการแนะนำเส้นทางที่ “ปลอดภัยกว่า”
- `expected_recorded_count` คืออัตราจำนวนรายการบันทึกที่คาดไว้ (research) ไม่ใช่ความน่าจะเป็นรายบุคคล ไม่รวมหลายช่วงถนนเป็นความเสี่ยงของเส้นทาง สี `base` ไม่ได้แปลว่าปลอดภัย วงกลมเป็นสัญลักษณ์ของช่วงถนน ~2 กม. ไม่ใช่รัศมีอันตรายหรือตำแหน่งเกิดเหตุ
- ผลประเมินยังไม่รวมสภาพอากาศ ฝน หรือวันหยุด/เทศกาลแบบปัจจุบัน แอปจึงไม่แสดงแผงข้อมูลเหล่านั้น (ประวัติแสดงสภาพอากาศ “ที่บันทึกไว้” ในอดีตเท่านั้น)
- วันที่หลัง 2025-12-31 เป็นฉากทัศน์วิจัย ไม่มีข้อมูลจริงให้เทียบ
- Photon และ OSRM demo อาจช้า จำกัดอัตรา หรือไม่พร้อม; ผลค้นหาขึ้นกับข้อมูล OpenStreetMap
- ยังไม่มีชุดทดสอบอัตโนมัติสำหรับ frontend
