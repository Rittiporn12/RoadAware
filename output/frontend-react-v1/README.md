# RoadAware frontend — วางแผนเส้นทางและดูจุดเสี่ยง (React + Vite, ต้นแบบงานวิจัย)

ผู้ใช้ค้นหาต้นทาง–ปลายทางในประเทศไทย → เห็นเส้นทางขับรถจริง → วงกลมสีบอกระดับเฝ้าระวังของช่วงถนนตลอดเส้นทาง (ประเมินตามเวลาที่คาดว่าจะผ่านแต่ละจุด) → แตะวงกลมเพื่อดูว่าที่ผ่านมาส่วนใหญ่เกิดเหตุแบบไหน (ฝนตก/แจ่มใส, ชนท้าย/พลิกคว่ำ ฯลฯ, สาเหตุที่บันทึก, ช่วงเวลาที่เกิดบ่อย)

## เริ่มใช้งาน (สอง terminal ที่ root ของ repo)

Terminal 1 — backend API (เหมือนเดิม):
```
.venv/bin/python backend/scripts/run_api_server.py
```

Terminal 2 — frontend (ต้องมี Node.js 18+; ครั้งแรกต้อง `npm install`):
```
cd frontend
npm install
npm run dev
```
เปิด **http://127.0.0.1:5173/** (ต้องเป็น origin นี้ เพราะ CORS ของ backend อนุญาตเฉพาะ 127.0.0.1/localhost:5173 และ :3000)

- เปลี่ยน API: `http://127.0.0.1:5173/?api=http://127.0.0.1:8001` หรือตั้ง `VITE_API_BASE`
- build ไฟล์ static: `npm run build` → `dist/` แล้ว `npm run preview` (พอร์ต 5173 เช่นกัน)
- หน้าตรวจ API สำหรับนักพัฒนา: http://127.0.0.1:5173/debug.html

## ทำงานอย่างไร
1. **ค้นหาสถานที่** — Photon (komoot) public demo กดค้นหา/Enter เท่านั้น จำกัด ≤1 ครั้ง/วินาที มี cache เฉพาะผลในไทย ไม่เลือกผลแรกให้อัตโนมัติ (ม.ศรีปทุมมีหลายวิทยาเขต, “เขาใหญ่” มีหลายแห่ง) หรือกด “เลือกบนแผนที่” แก้ข้อความแล้วสถานที่/เส้นทางเดิมถูกยกเลิก
2. **เส้นทาง** — OSRM public demo (`router.project-osrm.org`) แสดงระยะทาง/เวลาขับโดยประมาณ (ไม่รวมจราจรจริง) ถ้า OSRM ต้อง snap จุดไปถนนไกลกว่า 300 ม. จะแจ้ง ไม่มีการวาดเส้นตรงแทนเมื่อหาเส้นทางไม่ได้ เส้นทางแสดงได้เสมอแม้ backend ML ปิดอยู่
3. **ช่วงถนนบนเส้นทาง** — ดึง `GET /api/v1/segments` ใน bbox ของเส้นทางครบทุกหน้า แล้วจับคู่แบบระมัดระวัง: สุ่มจุดตามช่วงถนนทุก 100 ม. ช่วงถนนนับว่า “อยู่บนเส้นทาง” เมื่อ ≥50% ของจุดอยู่ห่างเส้นทาง ≤50 ม. (กันถนนที่แค่ตัดผ่าน) — เป็นการเชื่อมโยงโดยประมาณ ไม่ใช่ระดับระบบนำทาง
4. **เวลาที่ผ่านแต่ละจุด** — เวลาออก + (ระยะสะสม/ระยะทั้งหมด) × เวลาขับ → วันที่และช่วง 6 ชม. ของจุดนั้น ส่ง `POST /api/v1/spatial/predictions` (`unit: "6h"`) ทีละ ≤128 แถว ถ้า batch ใดล้มเหลวจะไม่แสดงผลบางส่วน
5. **วงกลม** — สีและระดับจาก `colour`/`colour_hex` ของ API (สูงสุด/สูง/ปานกลาง/ต่ำกว่าค่ากลาง) ช่วงถนนที่อยู่ห่างกัน <600 ม. ตามเส้นทาง (เช่น ฝั่งไป/ฝั่งกลับ) รวมเป็นวงเดียวแสดงระดับสูงสุด ส่วนเส้นทางที่ไม่มีข้อมูลเป็นสีเทา = ไม่ทราบ ไม่ใช่ปลอดภัย
6. **แตะวงกลม** — `POST /api/v1/spatial/history` (`unit: "daily"`, ย้อนหลัง 1827 วัน, top 5) สรุปเปอร์เซ็นต์จาก `categories.weather / accident_type / presumed_cause` และ `counts_by_time_block` ของเหตุที่บันทึกปี 2564–2568 แสดงใน popup และแผงรายละเอียด

## Backend
ไม่ได้แก้ backend — endpoint เดิม (segments, spatial/predictions, spatial/history ที่มี categories อยู่แล้ว) พอสำหรับ flow นี้

## ข้อจำกัด
- แบบจำลองครอบคลุมทางหลวง DOH 3,105 ช่วง (~2 กม.) ในพื้นที่นำร่อง (ลองจิจูด 100.2–102.0, ละติจูด 13.5–15.3 โดยประมาณ) เส้นทางนอกพื้นที่จะเห็นเส้นทางแต่ไม่มีวงกลม
- สีคือการจัดอันดับเชิงเปรียบเทียบของจำนวนเหตุที่คาดว่าจะถูกบันทึก ไม่ใช่ความน่าจะเป็นส่วนบุคคล ห้ามรวมเป็น “ความเสี่ยงของเส้นทาง”; วันที่หลัง 2025-12-31 เป็นฉากทัศน์วิจัย
- หมวด “สาเหตุ/สภาพอากาศ” เป็นคุณลักษณะที่บันทึกไว้ ไม่ใช่การพิสูจน์สาเหตุ และไม่ใช่สภาพอากาศปัจจุบัน
- Photon/OSRM/OSM tiles เป็นบริการ demo สาธารณะ ใช้ได้กับต้นแบบในเครื่องเท่านั้น ไม่มี SLA; `production_ready = false`
