# RoadAware: ข้อกำหนดหน้าผู้ใช้ที่ยืนยัน 12 พฤศจิกายน 2569

- เป็น Web App สำหรับผู้ใช้ทั่วไป ออกแบบ UX/UI พร้อม CSS โดยเน้นมือถือและรองรับ desktop ไม่ใช่หน้าทดสอบ API
- ค้นหาชื่อสถานที่ต้นทางและปลายทาง หรือเลือกตำแหน่งบนแผนที่ได้ทุกจุดในประเทศไทยที่หาเส้นทางรถยนต์เชื่อมถึงกันได้ ไม่จำกัดเฉพาะพื้นที่ที่โมเดลรองรับ
- ตัวอย่างเส้นทาง: มหาวิทยาลัยศรีปทุม → เขาใหญ่ ต้องมีการเลือกผลค้นหาเพื่อแยกวิทยาเขต/สถานที่ชื่อซ้ำ
- แสดงเส้นทางถนนจริง ระยะทางและเวลาเดินทางโดยประมาณ ไม่สร้างเส้นตรงปลอมแทนเส้นทาง
- แสดงวงกลมสีตามช่วงถนนบนเส้นทางที่มีผลประเมินจริง กดอ่านค่าคาดการณ์และประวัติได้ สีต้องมีข้อความกำกับ
- จำกัดการเลื่อน/ซูมและการแสดงพื้นที่แผนที่อยู่ในประเทศไทย
- การหาเส้นทางต้องไม่ขึ้นกับความพร้อมหรือความครอบคลุมของโมเดล เส้นทางยังแสดงได้แม้บริการประเมินไม่พร้อมหรือไม่มีข้อมูล ห้ามตีความไม่ทราบเป็นศูนย์หรือปลอดภัย
- เป้าหมายที่ผู้ใช้ย้ำเพิ่มเติม: ต้องประเมินเส้นทางได้และดูสภาพอากาศ/ฝนกับเทศกาล/วันหยุดของวันเดินทาง ไม่ใช่เพียงแสดงฟอร์ม
- ต้องแสดงข้อผิดพลาดที่เข้าใจง่ายและลองใหม่ได้ โดยคงต้นทาง ปลายทาง วันเวลาไว้
- Claude Code เป็นผู้แก้โค้ดผ่าน bridge ทีละงาน Codex ตรวจ diff และการทำงานจริง เปิด Terminal monitor ให้เห็นระหว่างทำงาน

## ขอบเขตการอนุญาตและช่องว่างที่ตรวจพบ

คำสั่งเริ่มต้นยังไม่ให้แก้ backend หรือฝึกโมเดลซ้ำ การขยาย UX/CSS และเส้นทางได้รับอนุญาตชัดเจนแล้ว ส่วนการขยาย backend/ข้อมูลอยู่ระหว่างรอคำตอบจากคำถามของ Codex จึงยังไม่แก้ backend และไม่ฝึกโมเดลซ้ำ

API ปัจจุบันรับรองเฉพาะ 3,105 ช่วงถนนทางหลวงที่ผ่านเกณฑ์ (`backend/config/spatial_inference_v3.json`) ไม่ใช่ทุกเส้นทางทั่วประเทศ อากาศที่ใช้ในโมเดลเดิมเป็น archive ที่ lag สองวันและจุดอ้างอิงระดับจังหวัด ไม่ใช่พยากรณ์อากาศวันเดินทางสด การแทนค่าด้วยอากาศสดโดยตรงเปลี่ยนความหมาย feature และต้องตรวจแยกต่างหาก ปฏิทินธนาคารไม่เท่ากับวันหยุดราชการหรือเทศกาลทั้งหมด

ส่วน frontend เส้นทางใช้บริการภายนอกสำหรับต้นแบบ local (Photon, OSRM, OSM tiles) แยกจากการพยากรณ์อุบัติเหตุจริงของ RoadAware บริการ demo ไม่ใช่โครงสร้างพื้นฐาน production ที่รับรอง uptime การประเมินครอบคลุมทุกเส้นทางและบริบทฝน/เทศกาลยังไม่ถือว่าสำเร็จเพียงเพราะหน้าเส้นทางเปิดได้
